# World Streaming Architecture

## Purpose

The playable mainland is intentionally larger than the original Foundation island, but world scale must not multiply the mobile render cost. The terrain remains one authoritative mathematical world for gameplay queries while visible presentation is partitioned into render chunks.

## Authoritative world vs render chunks

`ExpandedIslandTerrainSystem` owns world shape, terrain height, playability, slope, sand, shallow-water classification and deterministic satellite-island layout. These queries work anywhere in the world whether a visual chunk is currently rendered or not.

`WorldChunkSystem` owns presentation only. It partitions terrain meshes, shallow-water meshes, tree instancing, grass, ferns and static environment dressing into 72-unit chunks. Each frame it keeps the Ranger's immediate neighborhood available and uses the active camera frustum plus a bounded render distance for the surrounding chunks. Off-screen/distant chunk roots are hidden as a unit.

This separation is deliberate: collision, harvesting and future NPC navigation must not depend on whether a mesh happens to be on screen.

## Mainland scale and Day-1 compatibility

The mainland uses approximately 2x the previous linear coast scale. The existing Day-1 beach coordinates are preserved by shaping the old southern coast into a deep inlet. This prevents the tutorial spawn/resources/hunt route from becoming an inland location merely because the wider island grew around it.

The larger mainland adds outer regional ridges, valleys and highlands without creating a second terrain surface.

## Satellite islands

Satellite islands are deterministic procedural data generated from one fixed seed. Their angles, distance from the mainland, footprint dimensions, rotation, edge warp, elevation and connecting shoal parameters vary. The result should read as an irregular archipelago rather than five similarly sized islands at obvious compass points.

The deterministic seed is important: the world must remain stable between reloads and later saves even though the layout looks random.

## Shallow water

Deep water remains one inexpensive ocean plane plus the existing animated shimmer. Shallow water is sampled from the authoritative terrain depth and shoreline classification into chunk-owned translucent meshes. This lets turquoise shallows reach substantially inland across low coastal shelves, coves and sandbars instead of being a narrow decorative ring outside the coast.

Shallow-water traversal still uses normal terrain/collision rules. The water visual system does not introduce a second physics surface.

## Ranger water reaction

`WaterVisualSystem` owns a small fixed ripple pool. When the Ranger moves across traversable shallow water, pooled rings expand and fade at the water surface. The pool is bounded and re-used; no unbounded particle objects are created while walking.

Movement speed is not changed in this pass. If wading resistance is added later, it should be a player/actor movement modifier driven by the same `isShallowWaterAt()` world query rather than by render-mesh collision.

## Tree harvesting and occlusion

Forest trees are still generated by the established environment system and keep their stable `forest-tree-N` collision/harvesting IDs. After generation, the large global instanced batches are split by chunk. `WorldChunkSystem` stores the mapping from each stable tree ID to its chunk-local instance handles.

Tree harvesting and camera occlusion use that registry, so chopping/fading still changes the correct visual instance after batching is split. The fallback legacy global-batch path remains available to the focused regression tests.

## Performance rules

- Do not make collision or terrain queries conditional on chunk visibility.
- Do not reintroduce one global instanced grass/tree mesh spanning the full expanded world.
- Keep chunk roots at world origin transforms; instances retain world-space placement matrices.
- Keep deep ocean and distant-horizon silhouettes as a very small fixed number of draw calls rather than unnecessarily subdividing them.
- Prefer bounded pools/budgets for reactive effects.
- New world dressing that can become numerous should register with `WorldChunkSystem` rather than attaching directly to the permanent root.
